Chapter 1.2 · Equations

Chapter 1.2 · Boolean equations

A sure test, no searching

Tau gathers every “this must be 0” part of a rule into one equation. One short calculation then shows whether any value at all makes it true. No trying values one by one.

Any set of “must be 0” conditions merges into one equation, f(x) = 0. Boole: it has a solution exactly when f(0) · f(1) = 0, and then the solutions are exactly the x with f(0) ≤ x ≤ f(1)′ (Theorem 1.9).

For a rule

An impossible rule is caught by calculation, not by trying.

Ask Tau ›x = 0 && x = 1

Tau answers F: x cannot be 0 and 1 at once.

Tau answers F: here f(0) = f(1) = 1.

Chapter 2 · For all, there is

Chapter 2 · Quantifier elimination

“For all” and “there is” can go

“For every x” and “there is a y” sound like endless checking. In an atomless algebra, where every part splits into smaller parts, they can always be rewritten away, so the answer covers every value.

In an atomless Boolean algebra every nonzero element splits into two disjoint nonzero parts, and every quantifier can be eliminated. Equations merge into one; “not 0” conditions do not, but jointly hold iff none is identically 0 (Cor. 2.2). With atoms, a richer language is needed (counting atoms).

For a rule

The answer covers every value, not just the ones tried.

Ask Tau ›all x ex y x & y = 0 && x | y = 1

Tau answers T: every x has an exact opposite.

Tau answers T: every x has a complement, y = x′.

Chapter 6 · Sentences as values

Chapter 6 · NSO

A logic that can name its own sentences

Tau can use whole sentences as values, the way it uses numbers. Two sentences that mean the same count as one value. So a rule can talk about rules by what they mean, without the old paradoxes of sentences about themselves.

Sentences up to logical equivalence form a Boolean algebra. NSO quantifies over them as elements, so a formula speaks about formulas of its own language by meaning, never by text, unlike Tarski's setting (§6.1). If the base logics form an atomless algebra, satisfiability is decidable exactly when theirs is; otherwise decidable model counting is needed (§6.2).

For a rule

A running spec can carry its next version as a value.

Chapter 7 · Rules over time

Chapter 7 · GSSOTC

Time without peeking ahead

A rule runs one step after another. At each step it may look at now and a few steps back, never into the future. Before it runs, Tau checks that it can keep going forever, whatever comes in.

A spec reads the present and a fixed number of past steps, never the future. sat: for all inputs, are there time-compatible outputs that satisfy it forever? Decided by iterating to a fixed point.

For a rule

A rule that would get stuck later is caught now.

Ask Tau ›o1[t]:bv[2] > o1[t-1]:bv[2]

Tau answers F: 2 bits (0 to 3) cannot grow forever.

Chapter 8.3 · Updates

Chapter 8.3 · Pointwise revision

Change the rules, keep the rest

An update does not have to repeat the whole rule. The new rule always wins. Where it leaves a choice open, Tau keeps doing what the old rule did.

Old spec ϕ, new spec ψ, input x, output y, at each step:

χ = ψ(x,y) ∧ [(∃t. ϕ(x,t) ∧ ψ(x,t)) → ϕ(x,y)]

ψ always holds; where some output t meets both, ϕ holds too, keeping the most of the old behaviour.

For a rule

A small patch is enough; the rest keeps working.
