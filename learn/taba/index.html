The math under Tau, in plain words.

Five ideas from Ohad Asor's draft book on Boolean algebras, the math under Tau Language, and what each means for a rule.

Chapter 1.2 · Boolean equations

A sure test, no searching

Any set of “must be 0” conditions merges into one equation, f(x) = 0. Boole: it has a solution exactly when f(0) · f(1) = 0, and then the solutions fill one range, from f(0) to the complement of f(1).

For a rule

An impossible rule is caught by arithmetic, no search.

Ask Tau ›x = 0 && x = 1

Tau answers F: here f(0) = f(1) = 1.

Chapter 2 · Quantifier elimination

“For all” and “there is” can go

In an atomless Boolean algebra every nonzero value splits into smaller nonzero parts. There, “for all” and “there is” can always be rewritten away. Equations merge into one; “not 0” conditions do not.

For a rule

The core of how a Tau engine decides, not guesses.

Ask Tau ›all x ex y x & y = 0 && x | y = 1

Tau answers T: every x has a complement.

Chapter 6 · NSO

A logic that can name its own sentences

Sentences, counted as equal when they say the same, form a Boolean algebra too. NSO uses them as values, so a formula can speak about formulas of its own language without Tarski's old trap: it reads their meaning, never their text. It stays decidable when its base logics are.

For a rule

A running spec can carry its next version as a value.

Chapter 7 · GSSOTC

Time without peeking ahead

A spec runs step by step, reading now and a set number of steps back, never ahead. sat asks: whatever the inputs, is there always an output, forever? The engine repeats one check until nothing changes: a fixed point.

For a rule

A rule that would get stuck later is caught now.

Ask Tau ›o1[t]:bv[2] > o1[t-1]:bv[2]

Tau answers F: a 2-bit output cannot grow forever.

Chapter 8.3 · Pointwise revision

Change the rules, keep the rest

An update need not restate the whole program. The new spec always holds; among the outputs it allows, the engine prefers those the old spec allows too. So the old behaviour stays wherever the new spec leaves room for it.

For a rule

We did not check how the testnet applies changes.

After the book · ocLTL, 2026

Until and since

A 2026 paper by Ohad Asor shows how to decide whether a program exists for specs with all LTL time operators, past ones too, over data like Tau's. Our engine already has until, since, weak_until, release and trigger. Lessons 13 and 14 show two.

Ask Tau: until ›Run: since ›

until on an input: F. since: a switch with a memory.
